Scopen - A wireless oscilloscope

UCSB CE 2020 Capstone Project

Updated June 2020

Back to Projects

Concept

Scopen is one of the UCSB CE 2020 capstone projects. We built it because we wanted an affordable, wireless and handheld oscilloscope-like tool for everyday circuit debugging.

The project combines an analog front end, STM32 and ESP32 controllers, external memory, a touch interface and desktop software in a compact pen-shaped enclosure.

Hardware

The hardware system consists of two parts. The Analog Front End isolates and scales the input signal. The microcontroller system samples the AFE output and manages the surrounding peripherals.

The AFE uses several stages to isolate the input, scale it up or down and convert the output into a differential signal. The MCU system also includes external SRAM for sampled data, a touch sensor for interaction and a WiFi controller for communication with desktop and mobile software.

Compact board design

One challenge was fitting every component onto a compact board while keeping it possible to assemble by hand. Components were placed on both sides of a 2.45 by 0.73 inch, six-layer printed circuit board. The complete system is smaller than a piece of regular gum.

Firmware

The STM32 firmware is based mainly on the STM32 HAL library. For peripherals that needed special features, we wrote lower-level drivers with the STM32 LL library. One example is the I2C restart behavior needed for efficient communication with the touch sensor.

FreeRTOS allows the controller to run separate communication and general-logic tasks. The final STM32 implementation uses five threads. The ESP32 stack is based on Arduino and uses two threads for upstream and downstream communication.

Sampling

Accurate ADC timing could not depend on interrupts because context-switching time is unpredictable. HRTIM provides a fixed sampling trigger, and DMA moves each result from the ADC register to external SRAM.

Threads and communication

Semaphores avoid race conditions in the multithreaded design. One controls access to the SPI interface, while two others track empty and occupied queue slots.

Wireless communication uses UDP and TCP with message forwarding on the ESP32. Upstream sampling data moves between ESP32 and STM32 over SPI, while the lower-bandwidth downstream command channel uses UART.

Software

The desktop software follows a Model-View-Controller design pattern. The interface uses Java Swing, including custom-drawn knobs and a dark visual theme.

Industrial design

We designed the enclosure in Autodesk Fusion 360, printed it in 3D and assembled the complete prototype to make the project function as a real product.

Issues and improvements

  • The front-end software could be rebuilt with JavaScript, React and Electron to improve portability across platforms.
  • The current sampling accuracy and 8-bit resolution could be improved by enabling oversampling or increasing the sampling period.
  • The touch sensor works as a proof of concept, but it needs greater sensitivity and more reliable response to user input.
