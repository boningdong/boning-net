Affordable, wireless and handheld.

Scopen is one of the UCSB CE 2020 capstone projects. We built it not just to satisfy our curricular requirements, but also for ourselves. We wanted oscilloscope-like equipment that could make everyday circuit debugging easier.

Hardware

The hardware system consists of two parts. The Analog Front End isolates and scales the input signal, while the microcontroller system samples the AFE output and manages the surrounding peripherals.

The MCU system includes external SRAM for sampled data, a touch sensor for interaction and a WiFi controller for communication between the MCU and the desktop or mobile application.

Compact board design

One challenge was fitting every component on a compact board while keeping it possible to assemble by hand. Components were placed on both sides of a six-layer printed circuit board.

Firmware

The firmware coordinates sampling, memory, touch input and wireless communication across STM32 and ESP32 controllers.

Read the firmware architecture notes

The STM32 implementation is based mainly on the STM32 HAL library. For peripherals that needed special features, we wrote low-level drivers using the STM32 LL library as a wrapper over the registers. One example is the I2C restart behavior needed for efficient communication with the touch sensor.

External sensors sit above these low-level drivers. FreeRTOS allows the controller to run separate communication and general-logic tasks. The final STM32 implementation uses five threads. The ESP32 stack is based on Arduino and uses two threads for upstream and downstream communication.

Several semaphores avoid race conditions in the multithreaded design. One controls access to the SPI interface, while two others track empty and occupied queue slots.

Read the sampling and communication notes

Accurate ADC timing could not depend on interrupts because context-switching time is unpredictable. HRTIM provides a fixed sampling trigger, and DMA moves each result from the ADC register to external SRAM.

Wireless communication uses UDP and TCP with message forwarding on the ESP32. Upstream sampling data moves between ESP32 and STM32 over SPI, while the lower-bandwidth downstream command channel uses UART.

Software

The desktop software follows a Model-View-Controller design pattern. The interface uses Java Swing, including custom-drawn knobs and a dark visual theme.

Industrial design

We designed the enclosure in Autodesk Fusion 360, printed it in 3D and assembled the complete prototype to make the project function as a real product.

Issues and improvements

Portable front-end software

The front-end software could be rebuilt with JavaScript, React and Electron to improve portability across platforms.

Sampling accuracy and resolution

The current sampling accuracy and 8-bit resolution could be improved by adjusting the parameters, enabling oversampling or increasing the sampling period.

Touch sensor sensitivity

The touch sensor works as a proof of concept, but it needs greater sensitivity and more reliable response to user input.
