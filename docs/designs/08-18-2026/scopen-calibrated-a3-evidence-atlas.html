Project / 2020

Scopen A wireless oscilloscope for portable circuit debugging.

A three-person UCSB capstone spanning mixed-signal hardware, real-time firmware, wireless communication, interface design, and a 3D-printed enclosure.

HardwareFirmwareIndustrial design

EmbeddedPCBFreeRTOS
Project thesis

A lab instrument, reduced to its essential signal path.

Scopen captures an analog signal at the probe, processes it on a compact embedded system, and sends the waveform wirelessly to a desktop application. The project asks how much of an oscilloscope can become portable without making the debugging experience feel disposable.

Evidence set / Hardware

Compactness was a system constraint, not a styling decision.

Figure H.01Analog front end isolates, scales, and converts the input to a differential signal.
Signal conditioning

Prepare the signal before asking the controller to understand it.

The analog path uses separate stages for isolation, gain selection, and differential conversion. This keeps the sampling system focused on acquisition and movement of already conditioned data.

Figure H.02Six PCB layers support the dense, two-sided component arrangement.
Physical system

Six layers inside a footprint smaller than a piece of gum.

Components sit on both sides of the 2.45-by-0.73-inch board. The layer stack gives mixed-signal routing, memory, power, and wireless control enough separation without expanding the probe body.

Evidence set / Firmware

The timing-critical path stays in hardware.

Figure F.01HRTIM triggers the ADC; DMA moves the sample into external SRAM.
Deterministic acquisition

Trigger first. Transfer without interrupting.

Software interrupts introduce timing variation. The high-resolution timer controls the sample instant directly, while DMA handles memory transfer after conversion.

Figure F.02Five threads coordinate communication and product logic.
Concurrent system

Use threads where exact sample timing no longer matters.

FreeRTOS separates data movement, commands, and general logic. Semaphores protect the shared SPI interface and coordinate the producer-consumer queues.

Evidence set / Product

A working system still has to read as an instrument.

Figure P.01Java Swing interface organized around the waveform.
Desktop client

Keep the waveform visually dominant.

The Java client follows a model-view-controller structure. Custom-drawn controls make the dark interface feel closer to a dedicated instrument than a general desktop application.

Figure P.02Fusion 360 enclosure translated the electronics into a handheld probe.
Industrial design

Test the interaction at product scale.

We modeled, printed, and assembled the enclosure around the completed boards. That physical prototype made placement, access, and handling constraints visible before the final presentation.

Reflection

What the next version should resolve.

Final frameA portable prototype that connects electrical, computational, and physical design.
Next iteration

Improve accuracy before adding breadth.

A future version would trade some speed for higher sampling accuracy, improve touch sensitivity, and replace the desktop client with a portable web-based implementation.
